# XGBoost DART

This correctness-gated lane exercises FortML's bounded XGBoost DART policy
(`booster="dart"`). Each boosting round uses a compiler-independent integer
hash stream to select prior trees, then normalises the selected prior trees
and the new tree by `1/(k+1)`. Per-tree scales, booster metadata, staged
margins, additive contributions, warm-start suffixes, and schema-v5 text
persistence are all part of the checked CPU contract. Fit remains discrete;
input JVP/VJP products retain the split-boundary refusal, and resident CUDA
prediction remains a typed refusal with no host fallback.

The independent NumPy oracle replays a depth-one squared-loss Newton booster
on `target=[0,0,10,10]` with `eta=0.5`, `l2=1`, `drop_rate=0.99`,
`max_drop=1`, and `seed=1729`. It predicts the final margin
`[3.0555555555555556, 3.0555555555555556, 6.9444444444444444,
6.9444444444444444]` and tree scales `[0.25, 0.5, 0.5]`. The release app
checks this vector, deterministic replay, contribution summation, schema-v5
round trip, warm-start parity, malformed-rate refusal, and the CUDA boundary.

Raw rows are in [`xgboost_dart.csv`](xgboost_dart.csv), generated by
[`scripts/bench_xgboost_dart.py`](../scripts/bench_xgboost_dart.py).

Reproduce with:

```bash
python3 -B scripts/bench_xgboost_dart.py \
  --fortml ../fortml --output results/xgboost_dart.csv
```

This is CPU correctness evidence, not resident CUDA performance evidence.
