# LightGBM DART

This correctness-gated lane exercises FortML's bounded LightGBM DART policy
(`boosting_type="dart"`).  Each round uses a compiler-independent integer hash
stream to select prior trees for dropout.  The selected trees and the new tree
are then tree-normalised by `1/(k+1)`, and each scale is persisted with the
model.  The implementation deliberately keeps the fit discrete: fixed-tree
input JVP/VJP products retain the existing split-boundary contract, while
resident CUDA prediction remains a typed refusal.

The independent NumPy oracle replays a depth-one squared-loss Newton booster on
`target=[0,0,10,10]` with `eta=0.5`, `l2=1`, `drop_rate=0.99`, `max_drop=1`, and
`seed=1729`.  It predicts the final margin
`[3.0555555555555556, 3.0555555555555556, 6.9444444444444444,
6.9444444444444444]` and tree scales `[0.25, 0.5, 0.5]`.  The release app
checks this prediction, seed replay, schema-3 persistence, warm-start
continuation, malformed-rate refusal, and the CUDA boundary.

Raw rows are in [`lightgbm_dart.csv`](lightgbm_dart.csv), generated by
[`scripts/bench_lightgbm_dart.py`](../scripts/bench_lightgbm_dart.py).

Reproduce with:

```bash
python3 -B scripts/bench_lightgbm_dart.py \
  --fortml ../fortml --output results/lightgbm_dart.csv
```

This is CPU correctness evidence, not resident CUDA performance evidence.
