# XGBoost fitted-ensemble slicing

The raw record is [`xgboost_slice.csv`](xgboost_slice.csv), generated by
[`scripts/bench_xgboost_slice.py`](../scripts/bench_xgboost_slice.py). The
release executable is `fortml_bench_xgboost_slice`.

The fixture fits three exact depth-one squared-loss trees to eight ordered
samples. The independent NumPy oracle replays every Newton stump and checks
that a two-tree slice equals the second staged prediction of the source while
remaining distinct from the complete three-tree ensemble. The API also refuses
a zero-length prefix with `FORTNUM_DOMAIN_ERROR`.

Slicing is structural CPU metadata/state work: it copies tree nodes and the
fitted objective, base margin, routing, constraints, and diagnostics without
refitting. It does not claim resident CUDA execution; tree prediction retains
the existing typed CUDA refusal until a resident tree kernel is linked.

Run:

```bash
.venv/bin/python -B scripts/bench_xgboost_slice.py \
  --fortml ../fortml --output results/xgboost_slice.csv
```
