# Bounded tree SHAP-like attributions

This correctness-gated lane checks the per-feature raw-margin explanation
contract of both `xgboost_t` and `lightgbm_t`. The four-row fixture has one
depth-one split on feature one, targets `[0,0,10,10]`, unit shrinkage, and
`l2=1`. NumPy independently computes the baseline `5`, the two leaf
corrections `-10/3` and `+10/3`, and the zero attribution for the unused second
feature. The complete FortML vectors are compared, including row additivity.

The exact subset implementation uses fitted XGBoost cover or LightGBM child
row-count proportions for omitted features. Models wider than twelve features
return a typed refusal rather than silently switching to an approximation.
CUDA is represented by an `unavailable` capability row because no resident tree
explanation kernel is linked; the device API returns `FORTNUM_NOT_IMPLEMENTED`
without a host fallback.

| workload | phase | device | result |
| --- | --- | --- | --- |
| XGBoost tree SHAP-like | fit/predict | CPU | maximum NumPy error `0.0` |
| LightGBM tree SHAP-like | fit/predict | CPU | maximum NumPy error `0.0` |
| Both explanation APIs | capability check | CUDA | typed refusal `FORTNUM_NOT_IMPLEMENTED` (3) |

The raw records are in [`TREE_SHAP.csv`](TREE_SHAP.csv), generated by
[`scripts/bench_tree_shap.py`](../scripts/bench_tree_shap.py). Reproduce with:

```bash
python3 -B scripts/bench_tree_shap.py \
  --fortml ../fortml --output results/TREE_SHAP.csv
```
