# LightGBM query-weighted ranking

This correctness-gated lane exercises `lightgbm_t%fit_ranking` with the
`rank:pairwise` objective. Positive query IDs isolate pairs, unequal
relevance labels contribute the stable logistic loss and positive Newton
Hessian, and optional row weights use the smaller endpoint weight. The fitted
model emits raw margins with a zero base margin. Query-group validation and
the typed CUDA refusal are part of the public contract.

The independent NumPy oracle uses margins `[0,0,0]`, relevance
`[1,0,0]`, groups `[1,1,2]`, and weights `[2,4,7]`. It obtains pair loss
`log(2)`, gradient `[-1,1,0]`, Hessian `[0.5,0.5,0]`, and zero cross-query
contribution. The two-row release fixture has the exact Newton leaf margins
`[-2,2]`, with zero oracle error.

Raw rows are in [`lightgbm_ranking.csv`](lightgbm_ranking.csv), generated by
[`scripts/bench_lightgbm_ranking.py`](../scripts/bench_lightgbm_ranking.py).

Reproduce with:

```bash
python3 -B scripts/bench_lightgbm_ranking.py \
  --fortml ../fortml --output results/lightgbm_ranking.csv
```

This is CPU correctness and timing evidence, not resident CUDA performance
evidence. The CUDA row records the explicit `FORTNUM_NOT_IMPLEMENTED` status.
