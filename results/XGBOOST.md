# Exact depth-limited second-order boosting workload

Run date: 2026-08-07. The raw record is
[`xgboost_workloads.csv`](xgboost_workloads.csv), generated by
[`scripts/bench_xgboost.py`](../scripts/bench_xgboost.py). The release Fortran
workload is `fortml_bench_xgboost` and is rebuilt with `fo build --flag -O3`
before each run.

## What is checked

The workload uses 192 samples and three features. It grows twelve deterministic
depth-two trees with exact sorted thresholds at every node. The regression objective uses
L1=0.15, L2=1.5, gamma=0.01, minimum child Hessian 0.1, and learning rate
0.25. The logistic objective uses L1=0, L2=1, the same gamma, minimum child
Hessian, and learning rate. The NumPy oracle recursively reconstructs the
base score, gradient/Hessian arrays, regularized leaf weights, split gains,
depth limit, minimum leaf constraints, deterministic feature/threshold tie
order, and all staged predictions. It also checks the public first-tree root
diagnostics reported by the release app.

The recorded Fortran rows pass with maximum absolute oracle errors of
`7.11e-14` for squared loss, `3.70e-13` for binary logistic loss, and
`4.27e-13` for one-vs-rest multiclass probabilities. The six-row missing-value
fixture also passes with zero oracle error: its learned default branch sends
the NaN sample left at the exact gain tie policy and reproduces the analytic
prediction vector. The current gfortran CPU timings are:

| squared objective / fit | 3.640435e-4 | MSE 2.3896623698615184e-3 |

Timings are machine-specific. The CSV records compiler flags, source commits,
Python/NumPy versions, and the optional XGBoost package version.

## Validity boundary

This lane measures FortML's exact depth-two second-order estimator. It covers
recursive per-node gradient/Hessian aggregation, L1/L2 leaf regularisation,
gamma split penalties, minimum child Hessian, minimum leaf size,
deterministic feature/threshold order, and shrinkage. Predictions expose raw
margins, probabilities for logistic loss, and a piecewise input JVP. The
multiclass rows fit one recursive binary logistic model per sorted label,
normalize the positive OVR probabilities, and check the same exact-split
formulas independently with NumPy.

The `xgboost_missing` rows use six samples, one finite feature, and one IEEE
NaN. The independent oracle enumerates finite thresholds and both missing
default directions, checks the regularized gain and all six predictions, and
requires the stored branch to be reused at prediction time. The CSV also keeps
explicit `xgboost_histogram` and `lightgbm_histogram` unavailable rows: weighted
quantile/histogram growth, LightGBM leaf-wise/GOSS/EFB policies, and their GPU
variants are not silently represented by the exact CPU lane.

The optional `xgboost_reference` row is a dependency check. An installed
XGBoost release is contextual because histogram construction, tie handling,
tree depth, and missing-value routing require a separately matched workload.
An unavailable package is recorded as a refusal row.

## Reproduce

```bash
.venv/bin/python -B scripts/bench_xgboost.py \
  --fortml ../fortml --output results/xgboost_workloads.csv
```

The command rebuilds the shared FortML `fo` tree serially. Do not run another
FortML build concurrently. Independent NumPy checks run before the CSV is
written.
