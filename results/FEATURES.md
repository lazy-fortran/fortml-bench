# MLP, basis-pipeline, and tree workload

Run date: 2026-08-07. The raw record is
[`features_workloads.csv`](features_workloads.csv), generated by
[`scripts/bench_features.py`](../scripts/bench_features.py). The release
Fortran app is `fortml_bench_features`. It is built with `fo build --flag
-O3` before each run.

## What is checked

The lane contains four families of complete calls:

- `mlp_training` trains a deterministic 3-8-1 tanh MLP for 24 full-batch
  Adam epochs. NumPy reproduces the Xavier/phase initializer, MSE plus L2
  objective, reverse product, and bias-corrected Adam update. Initial loss,
  final loss, and the first eight predictions agree to below `5e-12`.
- `basis_pipeline` evaluates a horizontal degree-3 polynomial plus two-harmonic
  Fourier pipeline on 256 two-dimensional samples. NumPy checks the feature
  sum, input/parameter JVP sum, and parameter/input VJP sums. The pipeline
  uses exact log-frequency tangents, not finite differences.
- `decision_stump` checks the exhaustive squared-error split, leaf values,
  predictions, and piecewise-constant result against an independent NumPy
  split search. The prediction JVP is zero away from split boundaries.
- `gradient_boosting_regressor` checks 16 sequential residual stumps against
  an independent NumPy implementation. The matched scikit-learn
  `GradientBoostingRegressor` row is a second behavioral reference and agrees
  on this depth-1 fixture to floating-point roundoff.

## Reference boundaries

The scikit-learn MLP row is a contextual optimizer comparison: its estimator
initialization and update details are not expected to be bitwise identical to
FortML. The scikit-learn depth-1 boosting row uses the same learning rate,
number of estimators, and minimum leaf size, and matches the fixture's
predictions to roundoff.

PyTorch, JAX, and XGBoost are represented by explicit dependency-check rows.
On the recorded machine PyTorch is installed but is not timed by this lane.
the existing model-workloads benchmark covers its MLP forward/VJP product.
JAX and XGBoost are unavailable, so no timing or quality claim is inferred for
either package. An unavailable package is a refusal row, never an omitted
competitor.

## Reproduce

```bash
.venv/bin/python -B scripts/bench_features.py \
  --fortml ../fortml --output results/features_workloads.csv
```

The command rebuilds the shared FortML `fo` tree serially. Do not run another
FortML build concurrently. The benchmark's independent-oracle checks execute
before the timing rows are written.
