# Monotonic XGBoost-style tree constraints

The raw record is [`xgboost_monotonic_constraints.csv`](xgboost_monotonic_constraints.csv), generated by [`scripts/bench_xgboost_constraints.py`](../scripts/bench_xgboost_constraints.py). The release executable is `fortml_bench_xgboost`; it is rebuilt with `fo build --flag -O3` before the run.

The workload uses 192 samples, two features, eight depth-three trees, and an independent 257-point query grid with the second feature held fixed. The exact lane uses a `+1` constraint on feature one; the weighted-histogram lane uses `-1`. The NumPy harness parses the complete query vectors and recomputes the maximum adjacent monotonicity violation itself. All four CPU rows pass with zero violation. Timings are machine-specific and are retained only for the CPU rows.

The implementation propagates leaf-value bounds through recursive splits. A split on a `+1` feature receives a shared lower/upper boundary between child subtrees; `-1` reverses the bounds. Unconstrained features preserve the current bounds. The fit remains a discrete tree-building operation, so input JVP/VJP products retain the existing split-surface refusal contract.

CUDA is deliberately represented by two `unavailable` capability rows. No resident CUDA tree or histogram kernel is linked in this release, and the public `predict_device` contract returns `FORTNUM_NOT_IMPLEMENTED` instead of silently executing on the host. These rows are not GPU timings.

Run:

```bash
.venv/bin/python -B scripts/bench_xgboost_constraints.py \
  --fortml ../fortml --output results/xgboost_monotonic_constraints.csv
```
