# Production Lion trainer benchmark

Run date: 2026-08-08. The raw record is
[\`lion_training.csv\`](lion_training.csv), generated by
[\`scripts/bench_lion_training.py\`](../scripts/bench_lion_training.py).

The lane trains a two-parameter linear MLP for 64 epochs with two
four-sample updates per epoch. It uses learning rate \`2e-3\`, \`beta1=0.9\`,
\`beta2=0.99\`, decoupled weight decay \`1e-3\`, and EMA decay \`0.9\`. The NumPy
rows implement the gradient, sign interpolation, momentum, weight decay, and
EMA recurrence independently. FortML CPU rows are retained only when their
final loss and EMA norm agree within \`2e-12\`. The checkpoint row records the
maximum parameter error between an uninterrupted run and a 32-epoch checkpoint
resume.

The release app is \`fortml_bench_lion_training\`. On the recorded run the
FortML rows report a final-loss error of \`6.94e-18\`, an EMA-norm error of zero,
and a resumed-trajectory error of zero. The CPU trainer reports
\`2.92401e-4\` seconds for the 64-epoch trajectory and
\`2.55281e-4\` seconds for the split checkpoint trajectory. These values are
correctness-gated timings for this small workload.

CUDA rows are explicit \`unavailable\`: resident Lion state is not linked, and
the harness does not relabel host execution as device evidence. Derivatives
through the sign branch and optimizer hyperparameters remain separate
capability gates.

Reproduce:

\`\`\`bash
python3 -B scripts/bench_lion_training.py \
    --fortml ../fortml --output results/lion_training.csv
\`\`\`
