# Compact-support sparse product

This is a separate workload from the Gaussian pairwise benchmark. It applies
the one-dimensional Wendland C2 compact-support kernel on an integer grid with
support radius 8, diagonal shift 0.08, float64 arithmetic, and four right-hand
sides. Every implementation uses the same deterministic input. The independent
oracle is a row-wise NumPy sum over only the analytically nonzero neighbors;
the Fortran benchmark also checks that oracle before timing.

FortML builds the triplets through `fortsparse`, retains a CSR view, and runs
host or resident OpenACC row-owned products. KeOps evaluates the same formula
as a dense pair reduction, so this comparison measures the benefit of exposing
compact support to the sparse backend. It is not a claim that KeOps' generic
pairwise path has been given a sparse range index. GPyTorch is not listed for
this custom compact-support kernel because its built-in RBF/KeOps baseline is a
different mathematical operator.

All timings are seconds per 4-RHS product, with setup excluded from resident
curves. CPU rows use one thread. The GPU is an NVIDIA GeForce RTX 5060 Ti;
Fortran uses `nvfortran 26.5 -O3 -acc`, and Python uses PyTorch 2.13.0+cu130
and PyKeOps 2.3. The raw CSV records compiler flags, versions, precision,
nonzeros, CSR storage bytes, setup, runtime, status, and oracle error.

| device | N | FortML resident | KeOps resident | dense PyTorch resident |
| --- | ---: | ---: | ---: | ---: |
| CPU | 512 | 0.0171 ms | 0.8178 ms | 3.4498 ms |
| CPU | 4096 | 0.1370 ms | 4.0650 ms | 398.0116 ms |
| CPU | 8192 | 0.2567 ms | 14.5432 ms | 1558.8222 ms |
| CUDA | 512 | 0.0687 ms | 0.8501 ms | 0.1310 ms |
| CUDA | 4096 | 0.1196 ms | 3.9771 ms | 14.3844 ms |
| CUDA | 8192 | 0.2343 ms | 14.4690 ms | OOM |
| CUDA | 16384 | 0.4557 ms | 42.6064 ms | OOM |

The FortML resident CUDA curve remains below both available competitors at
every matched GPU size. From N=512 to 16384 it grows by 6.63x for a 32x
increase in samples, consistent with the fixed-radius O(N) sparse product;
KeOps grows by 50.1x on the same GPU sizes. The dense PyTorch OOM boundary is
recorded at N=8192 on this 16 GiB GPU for the float64 pairwise construction.
